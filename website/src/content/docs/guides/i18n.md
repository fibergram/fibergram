```bash
pnpm add @fibergram/i18n
```

The Effect-native analogue of grammY's `@grammyjs/i18n` and aiogram's `I18n`
middleware, over [Fluent](https://projectfluent.org). Translate with
`t(key, vars)` through an **ambient locale**: no context object, nothing passed
down the call stack.

## Build a translator

`I18n.make` is synchronous — Fluent parsing is pure — so the value can build
routes before any `Layer` exists:

```ts
import { I18n } from "@fibergram/i18n"

const i18n = I18n.make({
  defaultLocale: "en",
  locales: {
    en: `
hello = Hello, { $name }!
menu-button = Menu
`,
    ru: `
hello = Привет, { $name }!
menu-button = Меню
`
  }
})
```

In a real bot the sources come from `.ftl` files you read at startup — Fluent's
own format, with plurals, selectors, and message attributes.

## Translate

```ts
import { Chat } from "@fibergram/core"
import { Effect } from "effect"

const greet = Effect.gen(function* () {
  const text = yield* i18n.t("hello", { name: "Ada" })
  yield* Chat.reply(text)
})
```

`t` resolves the locale itself and **adds nothing to `R`**.

Or reach the translator through `R` with the free accessors, providing
`I18n.layer(i18n)` at the edge — useful when the catalog is assembled inside the
layer graph:

```ts
import { I18n } from "@fibergram/i18n"

const greet = Effect.gen(function* () {
  const text = yield* I18n.t("hello", { name: "Ada" })
  return text
})
```

## How the locale is picked

First hit wins:

1. an explicit `I18n.withLocale("ru")` override,
2. the preference persisted by `setLocale` through the `DialogStore` port
   (skipped when no store is in context),
3. the sender's `languageCode` on the update being handled,
4. `defaultLocale`.

Tags are negotiated against the loaded locales: exact → case-insensitive →
primary subtag (`"pt-BR"` finds a `"pt"` bundle) → default.

```ts
// inside any handler — persist the sender's choice
const toRussian = i18n.setLocale("ru")
```

The preference is stored under an `i18n:locale` kind, scoped per user by default,
so a durable [`DialogStore`](/concepts/persistence/) makes it durable for free.
Reads are opportunistic: `t` works with no store in context at all.

## Localized `hears`

Reply-keyboard presses come back as plain localized text, which is awkward: you
would have to match against every translation of the label. `i18n.hears` matches
the key's translation in **any** loaded locale and tells the handler which one
matched:

```ts
import { Router } from "@fibergram/core"
import { Effect } from "effect"

const router = Router.make(
  i18n.hears("menu-button", (locale) => Effect.log(`menu opened in ${locale}`))
)
```

It carries `kinds: ["message"]`, so `Router.allowedUpdates` derives the
subscription as usual.

## The API

| Export | What it is |
|---|---|
| `I18n.make(options)` | Synchronous constructor over `.ftl` sources per locale tag |
| `I18n.I18n` | Service tag for the translator |
| `I18n.layer(service)` | `Layer<I18n>` wiring a `make` value into `R` |
| `I18n.t(key, vars?)` | Free accessor: format in the current locale |
| `I18n.locale` | Free accessor: the negotiated current locale |
| `I18n.setLocale(tag)` | Free accessor: persist the preference |
| `I18n.withLocale(tag)` | Scope an explicit override around an effect |
| `I18n.currentLocale` | The ambient override reference itself |

On the `make` value: `t`, `locale`, `setLocale`, `translate(locale, key, vars?)`
(a pure per-locale lookup returning `Option<string>`), `hears`, plus `locales`
and `defaultLocale`.

## Failure model

- **A missing key** falls back to the default bundle. Missing from *both* is a
  programming error and dies as a defect — a user should never see a raw message
  id.
- **A missing variable** is not fatal: Fluent renders its `{$name}` placeholder.
- `useIsolating` defaults to `false`, so formatted text round-trips through
  Telegram cleanly and `hears` can exact-match. (Fluent's bidi isolation
  characters are invisible but would break both.)

## Pairing with menus

Menu labels can be `Effect`s, which is exactly what a localized label is:

```ts
Menu.make("main", { text: "…" }).text("lang", I18n.t("menu-button"), handler)
```

The label re-renders per user, in their locale, with no extra machinery. The
[restaurant-booking example](https://github.com/fibergram/fibergram/tree/main/examples/restaurant-booking)
does this for a full two-language menu.
