This site has two layers: the handwritten guides you are reading, and an API
reference generated from the source.

## The API reference is generated

Every public export carries JSDoc, and `pnpm docgen` turns it into markdown under
`packages/*/docs/modules/`. `website/scripts/sync-api-reference.mjs` then rewrites
that output into the Starlight collection: Jekyll frontmatter becomes Starlight
frontmatter, the hand-rolled table of contents is dropped, headings are demoted
one level, and `{@link …}` references are resolved into real cross-page links.

The generated pages under `src/content/docs/reference/` are **gitignored**. Never
edit them — the change would vanish on the next sync. Edit the JSDoc in the
source instead.

```bash
pnpm docgen              # regenerate packages/*/docs from the source
pnpm --filter @fibergram/website sync    # rewrite that into the site
pnpm --filter @fibergram/website dev     # both, then serve
```

:::note[The generated Bot API surface is excluded]
`@fibergram/core/client/generated` is ~5 MB of markdown mechanically derived from
Telegram's spec. Publishing it would produce three unreadable multi-megabyte
pages, so the sync skips it and links to
[Telegram's own reference](https://core.telegram.org/bots/api) instead.
:::

## The documentation gate

Every public export needs JSDoc with:

- a short description,
- a **compiling `@example`**,
- `@since`,
- optionally `@category`.

`pnpm docgen` is a **CI gate**. An `@example` that does not compile, or an
undocumented export, fails the build. That is why examples in the API reference
can be trusted: they were type-checked against the actual source.

```ts
/**
 * An in-memory {@link Dedup} backed by a `Ref<HashSet<number>>`.
 *
 * @example
 * import { Dedup } from "@fibergram/core"
 * import { Layer } from "effect"
 *
 * const layer: Layer.Layer<Dedup.Dedup> = Dedup.layerMemory
 *
 * @category layers
 * @since 0.1.0
 */
```

:::caution[Guide snippets are not compiled]
The `@example` blocks in the API reference are compiler-checked; the snippets in
these handwritten guides are not. When adding one, copy from a passing test or an
`@example` rather than writing it from memory, and prefer linking to the
reference over restating a signature that will drift.
:::

## The naming boundary

The Bot API speaks `snake_case`. fibergram does not.

`snake_case` may appear **only** inside the edge schema definitions in
`packages/core/src/client`, where `Schema.encodeKeys` maps `snake_case → camelCase`
on decode and back on encode. Everywhere else — handlers, tests, guides, examples
— is camelCase.

Seeing `snake_case` outside that boundary is a bug, not "a field from the API".
That includes documentation: writing `retry_after` in a guide teaches the wrong
model, so write `retryAfter` and mention the wire name only when discussing the
wire.

## Writing the guides

The guides live in `website/src/content/docs/`. English is the default locale and
lives at the root; Russian lives under `ru/` with the same paths.

- **Internal links** are absolute and end in a slash: `/concepts/dialogs/`. In
  Russian pages they carry the locale: `/ru/concepts/dialogs/`.
- **A missing translation is fine.** Starlight falls back to the English page and
  shows a "not translated" notice, so shipping an English-only page does not
  break the Russian site.
- **Sidebar entries** live in `astro.config.mjs`, with `translations` for the
  localized labels. A new page needs an entry there — the guides are not
  autogenerated, deliberately, because reading order matters.

## Changesets

Public behaviour changes ship with a changeset:

```bash
pnpm changeset
```

Documentation-only changes do not need one.

## Running the checks

```bash
pnpm build          # tsc -b across the project graph
pnpm typecheck      # src + test per package
pnpm test           # vitest
pnpm lint           # eslint, type-aware
pnpm docgen         # the documentation gate
pnpm circular       # madge
pnpm check:exports  # attw
```

CI runs all of them on every pull request.
