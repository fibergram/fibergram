Иногда нужен не диалог, а счётчик, выбранный язык или флаг «видел ли пользователь
туториал». `Session` — типизированный слот поверх того же порта `DialogStore`:

```ts
import { Session } from "@fibergram/core"

const counter = Session.make("counter", { initial: 0 })
```

## Внутри хендлера

`get` / `set` / `update` резолвят адрес из амбиентного контекста апдейта, поэтому
им не нужно ничего, кроме `DialogStore`, уже присутствующего в окружении диспатча:

```ts
import { Effect } from "effect"

const handler = Effect.gen(function* () {
  const count = yield* counter.update((n) => n + 1)
  yield* Chat.reply(`Сообщений: ${count}`)
})
```

## Вне хендлера

Рассылки и админские задачи адресуют явно:

```ts
const seen = yield * counter.getAt({ chatId: 555 })
yield * counter.setAt({ chatId: 555 }, 0)
```

У каждого амбиентного метода есть вариант с `At`. Это то же разделение, что между
[`Chat` и `TelegramClient`](/ru/concepts/no-ctx/#вне-хендлера).

## Область

```ts
const language = Session.make("language", { initial: "en", scope: "user" })
```

`scope: "chat"` (по умолчанию) ключует по чату; `scope: "user"` добавляет
отправителя, поэтому у каждого участника группы своё значение.

## Пространства имён

Ключи сессий несут kind вида `session:<name>`, поэтому две сессии с разными
именами — или сессия и диалог по одному адресу — никогда не видят состояния друг
друга. Префиксовать ключи вручную не нужно.

## Durable-режим достаётся от слоя

Сессии хранятся через `DialogStore`, поэтому вопрос персистентности решается
однажды на весь бот:

```ts
DialogStore.layerMemory //         исчезает при рестарте
PersistedDialogStore.layer //      durable, бесплатно
```

См. [Режимы персистентности](/ru/concepts/persistence/).

## `update` — это load-then-save

Не атомарный read-modify-write. На практике это нормально: апдейты одного адреса
уже сериализованы мейлбоксом `EntityManager`, поэтому сессия, чья область
совпадает с экстрактором ключа, записи не теряет.

Случай, за которым стоит следить, — область **шире** экстрактора. Сессия на чат
под экстрактором на пользователя работает по принципу «последний победил», потому
что два участника одной группы — это два разных адреса, работающих параллельно.

:::tip[Сессия или диалог?]
Берите `Session` для состояния, которое *читают и пишут* независимые в остальном
хендлеры: настройки, счётчики, флаги. Берите [`Dialog`](/ru/concepts/dialogs/) или
[корутину](/ru/guides/conversations/), когда состояние *и есть* разговор, то есть
когда от него зависит, что произойдёт дальше.
:::
