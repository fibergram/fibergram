```bash
pnpm add @fibergram/menu
```

`@fibergram/menu` — аналог `@grammyjs/menu` с одним структурным отличием:
навигационное состояние (стек «назад», текущая панель, номера страниц секций)
живёт в `DialogStore`, а не в эвристиках, угаданных по сообщению. «Устаревшее
меню» здесь состояние, о котором фреймворк знает, а не то, что он детектит.

## Объявить меню

Меню — дерево панелей:

```ts
import { Menu } from "@fibergram/menu"
import { Effect, Ref } from "effect"

const program = Effect.gen(function* () {
  const notifications = yield* Ref.make(false)
  const label = Effect.map(Ref.get(notifications), (on) =>
    on ? "Уведомления: ВКЛ" : "Уведомления: ВЫКЛ"
  )

  const settings = Menu.make("settings", { text: "Настройки" })
    .text("notif", label, Ref.update(notifications, (v) => !v))
    .row()
    .back("‹ Назад")

  const main = Menu.make("main", { text: "Главное меню" })
    .submenu("Настройки", settings)
    .url("Документация", "https://effect.website")

  return main
})
```

Подписи могут быть `Effect`. Именно это заставляет кнопки-переключатели работать
без специальной поддержки: после выполнения хендлера клавиатура перерисовывается,
и подпись читает новое значение.

## Отправить и смонтировать роут

```ts
import { Command, Router } from "@fibergram/core"
import { Menu } from "@fibergram/menu"
import { Effect } from "effect"

const start = Command.make("/start")

const router = Router.make(
  Router.command(start, () => Effect.asVoid(Menu.reply(main))),
  Menu.route(main)
)
```

`Menu.route` матчит нажатия на кнопки этого меню по префиксу `CallbackData`,
выполняет хендлер нажатой кнопки, обновляет сохранённое состояние, перерисовывает
сообщение и подтверждает callback-запрос. `Router.allowedUpdates(router)`
подхватывает `callback_query` автоматически.

## Пагинация

Пагинированная секция берёт элементы из `Effect` — статический массив через
`Menu.pages` или запрос к базе напрямую:

```ts
const catalog = Menu.make("catalog", { text: "Каталог" })
  .paginated("goods", {
    source: Menu.pages(
      [
        { id: "apl", label: "Яблоки" },
        { id: "bnn", label: "Бананы" },
        { id: "chr", label: "Вишня" }
      ],
      2
    ),
    onSelect: (id) => Effect.log(`выбрано ${id}`)
  })
  .row()
  .back("‹ Назад")
```

Рисует по одному элементу в ряд (настраивается через `columns`) плюс
навигационный ряд: `‹`, когда страница не первая, индикатор `· N ·` и `›`, пока
есть следующая. Коллбэк несёт только идентификаторы элементов.

## Как устроено состояние

- **Намерение в коллбэке, истина в сторе.** Payload говорит, *что нажали*
  (`["n","settings"]`, `["p","catalog","goods",2]`); стор хранит, *где на самом
  деле находится это сообщение*.
- **На каждое сообщение своё.** Состояние ключуется как `menu:<rootId>:<messageId>`,
  поэтому два живых меню в одном чате не делят стек. С
  `Menu.make(id, { scope: "user" })` в ключ входит id нажавшего, и каждый
  пользователь навигируется по одному и тому же сообщению независимо — то, что
  нужно для меню, опубликованного в группе.
- **Устаревшие вью пересинхронизируются.** Нажатие с клавиатуры, которая больше не
  является текущей панелью, **не** запускает хендлер: вместо этого сообщение
  перерисовывается в реальное состояние.
- **Отсутствие состояния деградирует мягко.** Чистый стор или деплой, переименовавший
  панели, трактуют нажатие как свежий корень. Ни падения, ни залипшего меню.

## Правила отрисовки

- Панели с `text` при навигации правят сообщение целиком (`editMessageText`);
  панели без текста — только клавиатуру (`editMessageReplyMarkup`).
- После каждого хендлера `text` / `onSelect` клавиатура перерисовывается, потому
  что подписи могли измениться. `MessageNotModified` от неизменившейся клавиатуры
  проглатывается.

## Бюджет байтов

Payload — компактные JSON-кортежи под префиксом `CallbackData` меню (по умолчанию
`menu-<id>`). `menu-main:["b","main","notif"]` — около 30 из 64 доступных байт,
поэтому держите идентификаторы панелей, кнопок и элементов короткими, примерно до
десяти символов. Слишком большие payload переливаются в `CallbackStore`, если он
подключён, — как у любого другого кодека. См.
[Callback data](/ru/guides/callback-data/).

## Durable-режим

`DialogStore.layerMemory` держит меню рабочими в пределах одного процесса;
`PersistedDialogStore` из [`@fibergram/durable`](/ru/guides/durable/) заставляет
открытые меню переживать рестарт. Код хендлеров одинаков.

## Заметки

- Ошибки и требования из хендлеров и подписей накапливаются в типе `Menu.route`
  ровно так же, как у роутов роутера, — один краевой `Layer` закрывает готового
  бота.
- Дублирующиеся id панелей в одном дереве — ошибка проводки, и она падает
  defect'ом. Использовать *одно и то же* значение подменю из двух родителей можно.
