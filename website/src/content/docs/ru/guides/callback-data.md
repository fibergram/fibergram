Telegram даёт каждой инлайн-кнопке 64 байта `callback_data` и никакой структуры.
Обычный итог — `"vote:42:yes"`, разбираемый через `.split(":")` на обратном пути,
причём правила разбора живут в двух местах, которые постепенно расходятся.

`CallbackData.make(prefix, schema)` делает из этого кодек:

```ts
import { CallbackData } from "@fibergram/core"
import { Schema } from "effect"

const Vote = CallbackData.make("vote", Schema.Struct({ id: Schema.Number }))
```

`prefix` — дискриминатор роутинга. В нём не может быть `":"` и `"#"`: это
разделители самого кодека.

## Кодирование, роутинг, декодирование

```ts
import { Chat, Router } from "@fibergram/core"
import { InlineKeyboard } from "@fibergram/core/ui"

// собираем клавиатуру из кодека
const keyboard = InlineKeyboard.empty.data("👍", Vote, { id: 1 }).data("👎", Vote, { id: 2 })

// роутим тем же кодеком — payload приходит уже декодированным
const route = Router.callback(Vote, ({ id }) => Chat.answerCallback({ text: `Голос за ${id}` }))
```

Совпадение — дешёвая проверка префикса (`matches`) до всякого декода, поэтому
роутер с двадцатью коллбэк-роутами не делает двадцать попыток декода на нажатие.

Полная поверхность кодека:

| Член | Что делает |
|---|---|
| `encode(value)` | → строка `callback_data`; падает `CallbackDataTooLong` |
| `decode(data)` | → значение; падает `CallbackDataMalformed` |
| `matches(data)` | дешёвая проверка префикса без декода |
| `parse(data)` | `decode` под защитой `matches` — `None`, если данные не наши |
| `button(text, value)` | `InlineKeyboardButton` с закодированным payload |

## Всегда отвечайте на коллбэк

Telegram крутит спиннер на нажатой кнопке, пока запрос не подтверждён:

```ts
Router.callback(Vote, ({ id }) =>
  Effect.gen(function* () {
    yield* recordVote(id)
    yield* Chat.answerCallback({ text: "Спасибо!" })
  })
)
```

`Chat.answerCallback()` без опций — тихое подтверждение.

## Когда 64 байт не хватает

`encode` падает `CallbackDataTooLong`, а не обрезает. Три выхода, по убыванию
предпочтительности:

**1. Ужать payload.** Имена полей — часть JSON. `{"i":42}` влезет там, где
`{"itemId":42}` может не влезть. Кортежная схема ещё компактнее — так внутри себя
устроен [`@fibergram/menu`](/ru/guides/menus/).

**2. Хранить идентификатор, а не данные.** Кнопка обычно должна нести ключ к
вашему состоянию, а не само состояние.

**3. Переливать в `CallbackStore`.** Подключите опциональный порт, и слишком
большие payload прозрачно уедут в него, а кнопка понесёт короткий ключ:

```ts
import { CallbackData } from "@fibergram/core"

Effect.provide(CallbackData.layerMemory)
```

`layerMemory` использует монотонные целочисленные ключи и **никогда ничего не
вытесняет**: для тестов и однопроцессного бота нормально, в продакшене это
неограниченно растущая мапа. Подложите Redis или KV — в порте всего два метода,
`put` и `get`.

:::caution[Стор перелива должен жить дольше сообщения]
Кнопка живёт столько же, сколько её сообщение. Если стор — память процесса и
процесс перезапустился, нажатия на старые сообщения декодируются в ничто. Либо
берите durable-стор, либо примите отказ и обрабатывайте `CallbackDataMalformed`
перерисовкой.
:::

## Callback data недоверенны

Кто видит кнопку, тот может подделать её `callback_data`. Схема гарантирует
*форму*, но никогда не *права доступа*: проверяйте разрешения в хендлере против
`Chat.from` ровно так же, как для команды.

То же касается идентичности: `callback_query` в группе приходит от того, кто нажал,
а это не обязательно тот, кому клавиатура предназначалась. Если разница важна,
кладите id нужного пользователя в payload и сравнивайте.

## Смежное

- [Диплинки](/ru/guides/deep-linking/) — та же дисциплина для payload `?start=`,
  с бюджетом в 64 *символа*.
- [Меню](/ru/guides/menus/) — целый навигационный слой поверх этого кодека, где
  payload говорит, *что нажали*, а стор хранит, *где находится сообщение*.
